# 项目任务分工建议（四人）

以下分工基于当前代码结构，将核心业务拆分为四个板块，便于并行开发与责任明确。每个板块都列出主要职责、关键代码文件以及交付物。若团队实际人数/经验不同，可按模块再细分或合并。

## A 组：订单与积分结算（负责人：同学 A）
- **职责**：
  - 维护订单创建/支付/退款全流程，保证金额与积分结算的正确性与幂等性。
  - 负责订单与会员的绑定逻辑（请求体 userId / `X-User-Id` 头解析），确保每笔订单都有归属用户。
  - 维护积分抵扣、积分折现金额、成长积分累加逻辑，处理库存扣减与订单状态机。
- **关键文件**：
  - `src/main/java/org/example/demomanagementsystemcproject/service/impl/OrderServiceImpl.java`（订单创建、积分结算、库存更新）。
  - `src/main/java/org/example/demomanagementsystemcproject/controller/OrderController.java`（入口校验与用户解析）。
  - `src/main/java/org/example/demomanagementsystemcproject/entity/OrderEntity.java`（订单积分字段、默认值、时间戳）。
  - `src/main/resources/db/migration/V22__ensure_order_points_tracking.sql` 等订单相关迁移（积分折扣、获积分字段）。
- **交付物**：
  - 完成订单全链路自测用例（创建/支付/退款/取消）。
  - 积分计算与金额校验的回归脚本（含非法请求场景）。

## B 组：会员画像与等级规则（负责人：同学 B）
- **职责**：
  - 维护会员档案聚合接口 `/api/member/me`，确保一次返回用户快照、积分规则、等级列表。
  - 负责等级判定、下一等级提示、积分余额的展示数据正确性。
  - 协调前端缓存刷新策略，确保订单后重新拉取最新会员信息。
- **关键文件**：
  - `src/main/java/org/example/demomanagementsystemcproject/service/impl/MemberServiceImpl.java`（会员画像聚合、等级判定与日志）。
  - `src/main/java/org/example/demomanagementsystemcproject/dto/MemberProfileDTO.java`（返回结构定义）。
  - `src/main/java/org/example/demomanagementsystemcproject/entity/Admin.java`（成长积分、可用积分字段及默认值）。
  - 等级/规则服务与 DTO（如 `MemberLevelService`、`PointsRuleService` 相关 DTO）。
- **交付物**：
  - 会员画像接口的契约文档与示例响应。
  - 等级与积分展示的校验用例（不同积分区间的等级边界测试）。

## C 组：积分商城与规则管理（负责人：同学 C）
- **职责**：
  - 维护积分商品上下架、库存、兑换流程；确保兑换前的积分校验、库存扣减、每日限次策略生效。
  - 维护积分规则（earn/redeem）的读取与前端下发，确保订单与兑换模块共享一致规则。
  - 协调与会员积分扣减/增加的接口调用或事件集成。
- **关键文件**：
  - `src/main/java/org/example/demomanagementsystemcproject/service/impl/PointsMallServiceImpl.java`（商品 CRUD、兑换、限次校验、积分扣减占位）。
  - 积分商品与兑换实体/仓储：`PointsGoodsEntity`、`PointsExchangeEntity` 及对应 Repository。
  - 积分规则服务/DTO：`PointsRuleService`、`PointsRuleDTO`。
- **交付物**：
  - 积分商品与兑换的接口清单、状态流转图。
  - 兑换流程的积分与库存一致性测试用例。

## D 组：数据库迁移与接口文档/质量保障（负责人：同学 D）
- **职责**：
  - 维护 Flyway 迁移脚本，确保新增字段（如订单积分、用户积分）与历史库兼容；负责回填/默认值策略审查。
  - 维护接口设计文档、错误语义与安全策略，支撑前后端对齐与新人入职。
  - 负责基础静态检查/编译校验，跟踪流水线异常并给出修复建议。
- **关键文件**：
  - `src/main/resources/db/migration/` 目录下的最新迁移脚本（例如 V18/V19/V20/V21/V22）。
  - `docs/接口设计报告.md`（接口设计与安全、幂等、扩展策略）。
  - 构建配置：`pom.xml`、`mvnw*`、`qodana.yaml` 等。
- **交付物**：
  - 迁移执行记录、回滚预案与手工校验步骤。
  - 接口文档更新与发布节奏说明；基础编译/静态扫描结果汇总。

## 协同约定
- **接口契约**：订单/会员/积分商城的字段命名与单位（金额/积分）保持一致，变更需同步文档与前端。
- **测试策略**：每个模块需维护最小可回归用例；关键链路（下单→积分发放→会员画像刷新→兑换）要有集成测试脚本或手工步骤。
- **发布节奏**：迁移脚本与后端变更需排在同一发布窗口；前端依赖的接口变更需提前 1 个迭代同步。
